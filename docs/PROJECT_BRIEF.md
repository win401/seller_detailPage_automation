# Project Brief

## 프로젝트명

Seller Detail Page Automation

## 한 줄 설명

상품 정보, 이미지, 경쟁 상세페이지 URL/메모를 입력하면 여러 AI 에이전트가 분석, 기획, 제작, 검수를 단계별로 수행하고, 사용자가 블록형 캔버스에서 간단히 수정한 뒤 플랫폼 업로드용 이미지 ZIP을 다운로드하는 웹 애플리케이션입니다.

## 문제 정의

초보 셀러는 상세페이지를 만들 때 다음 문제를 겪습니다.

- 상품 장점을 어떤 순서로 보여줘야 하는지 어렵습니다.
- 모바일에서 읽기 좋은 문구를 작성하기 어렵습니다.
- 디자인 툴 사용이 부담스럽습니다.
- 도매꾹 같은 도매 사이트에서 가져온 상품 이미지는 상세페이지에 바로 쓰기에는 퀄리티가 낮은 경우가 많습니다.
- 경쟁 셀러의 상세페이지를 참고하고 싶지만 어떤 포인트를 분석해야 하는지 막막합니다.
- AI가 바로 문구를 생성해도 전략, 구성, 검수 과정이 없으면 결과물이 가볍게 느껴질 수 있습니다.
- 플랫폼별 이미지 규격과 슬라이싱 작업이 번거롭습니다.
- 반복적으로 비슷한 톤앤매너를 다시 설정해야 합니다.
- 세로로 긴 상세페이지를 작업해야 해서 일반 가로 모니터뿐 아니라 세로 모니터에서도 편하게 볼 수 있어야 합니다.
- 장시간 작업하는 도구이므로 light/dark 모드를 지원해 작업 피로도를 줄여야 합니다.

## 해결 방향

이 프로젝트는 상세페이지 제작 과정을 에이전트 기반 워크플로우로 단순화합니다.

1. 상품 정보와 추가 제작 요청 입력
2. 이미지 업로드
3. 경쟁 상세페이지 URL/메모 입력
4. 분석 에이전트가 사용자가 제공한 URL/메모와 상품 정보를 바탕으로 경쟁 포인트를 정리
5. 기획 에이전트가 섹션 전략, 타깃, 톤앤매너, 이미지 방향을 설계
6. 제작 에이전트가 13섹션 상세페이지 초안을 생성
7. 검수 에이전트가 과장 표현, 근거 없는 수치/인증, 누락 섹션, 모바일 가독성을 점검
8. 모바일 상세페이지 캔버스 미리보기
9. 사용자가 수정 요청을 남기면 기획자 에이전트가 재기획
10. 재기획안을 바탕으로 제작/검수 에이전트가 새 시안 제출
11. 사용자가 필요한 경우 블록 단위로 간단히 수동 수정
12. 사용자 수정 이력과 스타일 선호를 저장
13. 프로젝트 저장
14. 플랫폼 업로드용 ZIP 다운로드

편집기는 데스크톱 웹 앱을 기준으로 만들되, 가로 모니터와 세로 모니터 모두에서 작업하기 좋은 반응형 레이아웃을 제공합니다.

앱 UI는 light/dark 모드를 지원하되, 상세페이지 캔버스의 최종 export 디자인은 사용자의 앱 테마와 분리해서 유지합니다.

## 백엔드 구조 원칙

이 프로젝트의 메인 백엔드는 Next.js와 Supabase를 중심으로 구성합니다.

- Supabase Auth: 회원가입, 로그인, 세션 관리
- Supabase PostgreSQL: 프로젝트, draft, 에이전트 실행 결과, 사용자 스타일 신호 저장
- Supabase Storage: 상품 이미지, 레퍼런스 이미지, 생성/개선 이미지 저장
- Next.js Route Handler: OpenAI API 호출, 가벼운 서버 로직, Supabase 연동

Python/FastAPI 백엔드는 현재 MVP의 필수 구조로 두지 않습니다. 다만 고도화 단계에서 Python 생태계가 꼭 필요한 기능이 생기면 별도 보조 서비스로 추가할 수 있습니다.

FastAPI/Python을 추가할 수 있는 후보:

- AI 누끼 제거
- OpenCV 기반 이미지 분석
- 레퍼런스 기반 이미지 합성
- 대량 이미지 전처리
- 데이터 분석/집계 배치
- 외부 수집 파이프라인

중요한 원칙은 FastAPI가 Auth, 메인 DB, 파일 저장의 중심을 다시 소유하지 않는 것입니다. 사용자, 프로젝트, draft, 에이전트 실행 결과, 이미지 파일의 기준 저장소는 Supabase로 유지합니다. FastAPI는 필요한 작업을 수행한 뒤 결과 URL이나 분석 결과를 Next.js 또는 Supabase에 돌려주는 보조 worker 역할로 둡니다.

## 성공 기준

데모에서 사용자가 상품 정보를 입력하고 AI 상세페이지 초안을 생성한 뒤, 캔버스에서 수정하고 ZIP 파일로 다운로드하는 전체 흐름을 보여줄 수 있어야 합니다.

사용자가 AI에게 수정을 요청할 때는 별도의 편집 에이전트를 두지 않습니다. 기획자 에이전트가 사용자의 수정 요청과 기존 검수 결과를 바탕으로 기획안을 다시 조정하고, 제작 에이전트와 검수 에이전트를 거쳐 새 시안을 제출합니다. 사용자는 최종 시안에서 필요한 부분만 간단히 수동 수정한 뒤 내보내기합니다.

경쟁 분석은 실제 자동 크롤링이 아니라 사용자가 입력한 경쟁 상세페이지 URL, 참고 메모, 캡처/요약 정보를 바탕으로 시작합니다. MVP에서는 법적/기술적 리스크를 줄이기 위해 외부 사이트를 자동으로 긁어오지 않고, URL은 참고 출처와 분석 맥락을 관리하는 입력값으로 사용합니다.

이미지 개선 기능은 원본 상품 이미지를 무작정 새로 만드는 기능이 아니라, 사용자가 업로드한 상품 이미지와 레퍼런스 이미지를 기준으로 상세페이지에 어울리는 배경, 조명, 구도, 분위기를 제안하고 개선 결과를 캔버스에 반영하는 흐름으로 설계합니다. 실제 상품의 형태, 색상, 소재, 구성품은 사용자가 제공한 정보에서 벗어나지 않아야 합니다.

## 현재 MVP 상태

2026-07-09 기준으로 얇은 end-to-end 흐름은 구현되어 있습니다.

- 새 프로젝트 생성 화면에서 상품 정보, 경쟁 URL/메모, 상품 이미지 입력 가능
- 분석 → 기획 → 제작 → 검수 에이전트 워크플로우 UI와 mock fallback 연결
- 13섹션 모바일 상세페이지 캔버스 렌더링
- 섹션 문구/이미지 편집, inline 수정, undo/redo, 선택 섹션 이동 일부 지원
- 기획자 에이전트 수정 요청 API route와 mock fallback 연결
- Supabase 저장/불러오기 구조와 localStorage fallback 연결
- 플랫폼 폭 기준 ZIP export 구현

아직 실제 AI API 품질 테스트는 완료하지 않았습니다. 따라서 AI 관련 문서는 "구조 연결"과 "실제 모델 응답 검증"을 분리해서 관리합니다. 현재 MVP는 API 키 또는 모델 호출 실패 시에도 데모가 끊기지 않도록 mock fallback을 유지합니다.
