# Feature Discussion Notes

## Purpose

이 문서는 상세페이지 AI 제작 프로그램의 기능 회의 내용을 누적 정리하기 위한 문서입니다.

현재 프로젝트는 수업 미니프로젝트를 우선 완성하고, 완성도가 충분히 올라간 뒤 사업화 가능성을 다시 검토합니다.

## Product Positioning

이 서비스는 피그마나 캔바처럼 사용자가 처음부터 자유롭게 디자인하는 툴이 아닙니다.

핵심 방향은 다음과 같습니다.

- 사용자가 상세페이지 구조를 몰라도 AI가 기본 흐름을 잡아준다.
- 사용자는 좋은 블록 조합을 선택, 수정, 재정렬한다.
- 디자인 자유도는 제한하되 결과물의 완성도와 제작 속도를 높인다.
- 초보 셀러가 조잡한 상세페이지를 만들지 않도록 도와준다.

정리하면, 이 서비스는 "자유 편집형 디자인 툴"이 아니라 "AI 기반 상세페이지 블록 에디터"입니다.

## M-01: 모바일 퍼스트 블록형 WYSIWYG 캔버스 에디터

### 기존 아이디어

모바일 화면 비율에 최적화된 세로형 캔버스에서 상세페이지를 편집합니다.

### 논의 결과

자유 편집형 에디터는 MVP 방향에 맞지 않습니다.

이유:

- 자유 배치, 리사이즈, 레이어 편집까지 제공하면 피그마/캔바와 경쟁하게 됩니다.
- 사용자가 다시 디자인 판단을 해야 하므로 서비스의 자동화 가치가 약해집니다.
- 초보 셀러에게 필요한 것은 무한한 자유도가 아니라, 망치기 어려운 구조입니다.

### 수정 방향

블록형 WYSIWYG 에디터로 정의합니다.

AI가 생성한 13개 상세페이지 섹션을 모바일 세로 캔버스에 자동 배치하고, 사용자는 제한된 범위에서만 편집합니다.

사용자가 할 수 있는 일:

- 섹션 순서 변경
- 섹션 문구 수정
- 섹션 이미지 교체
- 섹션 숨김 또는 삭제
- 추천 카피 후보 선택
- 템플릿 무드 변경

사용자가 하지 않는 일:

- 자유 좌표 배치
- 텍스트 박스 임의 생성
- 이미지 레이어 세밀 조정
- 피그마식 리사이즈/정렬 편집

### 핵심 문장

피그마는 잘 만드는 사람에게 좋은 도구이고, 이 서비스는 잘 몰라도 망하지 않게 해주는 도구입니다.

## M-02: 13대 섹션별 구조화 카피 생성 엔진

### 기존 아이디어

상품명과 키워드를 입력하면 AI가 상세페이지 13개 영역에 맞는 카피를 생성합니다.

### 논의 결과

단순히 긴 상세페이지 문구를 생성하는 방식은 적합하지 않습니다.

AI는 앱이 바로 사용할 수 있는 구조화된 섹션 데이터를 생성해야 합니다.

### 추천 13대 섹션

1. Intro: 첫 화면 감성 후킹 문구
2. One Line Selling Point: 상품 핵심 가치 한 줄 요약
3. Problem: 고객이 겪는 불편함
4. Solution: 상품이 문제를 해결하는 방식
5. Key Benefit 1: 가장 강한 장점
6. Key Benefit 2: 두 번째 장점
7. Key Benefit 3: 세 번째 장점
8. Detail Point: 소재, 구성, 크기, 사용법 등 구체 정보
9. Use Scene: 실제 사용 장면
10. Recommended For: 추천 대상
11. Trust Point: 관리법, 주의사항, 검수 포인트 등 신뢰 요소
12. FAQ: 구매 전 질문과 답변
13. CTA: 마지막 구매 유도 문구

### 사용자 입력 설계

사용자 입력은 최소화하되, AI가 좋은 결과를 만들 수 있을 만큼의 정보는 받아야 합니다.

원칙:

- 입력은 가볍게
- 출력은 엄격하게

필수 입력:

- 상품명
- 카테고리
- 핵심 키워드 3-5개
- 타깃 고객
- 상품 이미지
- 원하는 톤앤매너

선택 입력:

- 가격
- 소재/성분
- 사이즈
- 색상
- 구성품
- 주의사항
- 배송/교환 안내
- 강조하고 싶은 차별점
- 피하고 싶은 표현
- 참고 브랜드/무드

### UI/UX 입력 방식

모든 정보를 텍스트 입력으로 받으면 사용자가 피로감을 느낄 수 있습니다.

따라서 일부 정보는 체크박스, 토글, 선택칩 형태로 받는 것이 좋습니다.

텍스트 입력이 적합한 항목:

- 상품명
- 핵심 키워드
- 타깃 고객 직접 입력
- 강조하고 싶은 차별점
- 피하고 싶은 표현

선택 UI가 적합한 항목:

- 카테고리
- 플랫폼
- 톤앤매너
- 상세페이지 길이
- 타깃 고객 유형
- 강조 포인트
- 디자인 무드
- 포함할 섹션

체크박스 예시:

- 가성비 강조
- 프리미엄 이미지 강조
- 선물용 강조
- 사용 편의성 강조
- 소재/성분 강조
- 관리 쉬움 강조
- 배송/구성품 안내 포함
- FAQ 포함

톤앤매너 토글 예시:

- 지적인 인스타 피드 무드
- 다정한 블로그 공구 무드
- 담백 정보형 무드

## AI 출력 통제 방식

AI 출력은 우리가 강하게 규칙을 지정할 수 있습니다.

### 출력 규칙

- 반드시 13개 섹션으로 출력합니다.
- 섹션 id는 앱에서 정의한 값을 그대로 사용합니다.
- 각 섹션은 title, body, alternatives, imageHint를 포함합니다.
- 제목은 짧게 작성합니다.
- 본문은 모바일에서 읽기 쉬운 길이로 작성합니다.
- 상품 정보에 없는 성능, 인증, 효과를 지어내지 않습니다.
- 과장 광고 표현을 피합니다.
- FAQ는 구매 전 망설임을 줄이는 질문으로 구성합니다.
- CTA는 가격 압박보다 사용 장면과 구매 이유 중심으로 작성합니다.

### 추론 가능 영역

AI가 합리적으로 추론해도 되는 영역입니다.

- 타깃 고객이 느낄 불편함
- 사용 장면
- 추천 대상
- FAQ 질문
- 감성적 표현
- 상세페이지 흐름

### 추론 금지 영역

사용자가 제공하지 않았다면 AI가 만들어내면 안 되는 영역입니다.

- 의학적/기능성 효과
- 인증 여부
- 소재 성능 수치
- 세탁 가능 여부
- 원산지
- 배송 기간
- 할인율
- 재고/판매량

## Temperature 설정 논의

없는 말을 줄이기 위해 AI 모델의 temperature를 낮게 설정할 수 있습니다.

권장 방향:

- 구조화 JSON 생성: 낮은 temperature 사용
- 감성 카피 후보 생성: 중간 temperature 사용
- 사실 정보가 중요한 섹션: 낮은 temperature 사용

예시:

- 전체 상세페이지 JSON 초안: temperature 0.2-0.4
- 대체 카피 후보 생성: temperature 0.5-0.7
- FAQ/주의사항/신뢰 요소: temperature 0.2-0.3

단, temperature를 낮춘다고 hallucination이 완전히 사라지는 것은 아닙니다.

따라서 다음 장치가 함께 필요합니다.

- 출력 스키마 고정
- 금지 추론 영역 명시
- 앱 단의 검증 로직
- 비어 있는 정보는 "입력 필요" 상태로 표시
- 사용자가 확인해야 하는 문구 표시

## M-03: 무드 프리셋 기반 상세페이지 레이아웃 자동 매칭

### 기존 아이디어

기존 요구사항은 "핀터레스트 스타일 레이아웃 그리드 자동 매칭"이었습니다.

사용자가 카테고리를 선택하면 Pinterest API를 통해 트렌디한 레퍼런스 이미지를 추천하고, 그 감성에 맞춰 상품 이미지와 텍스트를 자동 배치하는 방향입니다.

### 논의 결과

MVP에서는 Pinterest API 연동을 핵심 기능으로 두지 않는 것이 적합합니다.

기획자가 납득할 수 있는 핵심 이유는 다음과 같습니다.

- Pinterest API 연동은 API 정책, 인증, 검색 품질, 저작권 이슈를 함께 검토해야 합니다.
- 외부 레퍼런스를 그대로 가져오면 MVP의 핵심인 "상세페이지 제작 흐름"보다 외부 데이터 연동이 더 큰 일이 됩니다.
- 사용자는 실제 Pinterest 이미지 자체보다 "Pinterest처럼 감도 있는 여백, 구도, 분위기"를 원합니다.
- 수업 미니프로젝트에서는 실시간 레퍼런스 수집보다 내부 프리셋으로 일관된 결과물을 보여주는 편이 더 안정적입니다.

따라서 MVP에서는 "Pinterest API 연동"이 아니라 "Pinterest 스타일을 참고한 내부 무드 프리셋"으로 구현합니다.

### 기능명 수정 제안

기존 이름:

- 핀터레스트 스타일 레이아웃 그리드 자동 매칭

MVP 이름:

- 무드 프리셋 기반 상세페이지 레이아웃 자동 매칭

사업화 확장 이름:

- Pinterest 연동 레퍼런스 무드보드 및 레이아웃 추천 엔진

### MVP 구현 방향

사용자는 Pinterest 이미지를 직접 고르지 않습니다.

대신 다음 항목을 선택합니다.

- 상품 카테고리
- 디자인 무드
- 이미지와 텍스트의 비중
- 강조하고 싶은 상세페이지 흐름

앱은 이 선택값을 바탕으로 내부 디자인 프리셋을 적용합니다.

예시 무드 프리셋:

- 미니멀 패션: 넓은 여백, 큰 이미지, 짧은 감성 카피
- 감성 오브제: 따뜻한 배경색, 제품 컷 중심, 부드러운 문장
- 프리미엄 뷰티: 고대비 타이포, 뉴트럴 색상, 신뢰감 강조
- 담백 정보형: 기능, 스펙, FAQ 가독성 강조
- 블로그 공구형: 친근한 말투, 추천 대상, 구매 전 걱정 해소 중심

### 레이아웃 자동 매칭 방식

AI가 생성한 13개 섹션에 대해 앱이 섹션별 블록 타입을 자동 배정합니다.

예시:

- Intro: 큰 이미지 + 메인 타이틀
- One Line Selling Point: 짧은 한 줄 카피 중심 블록
- Problem/Solution: 문제 제기와 해결 설명 블록
- Key Benefit: 3개 장점 카드 또는 리스트
- Detail Point: 이미지 + 상세 설명
- Use Scene: 사용 장면 중심 이미지 블록
- Recommended For: 추천 대상 리스트
- Trust Point: 신뢰 요소 또는 안내 블록
- FAQ: 질문/답변 리스트
- CTA: 마지막 구매 유도 영역

이 방식은 사용자가 디자인을 직접 하지 않아도 상세페이지의 시각적 흐름이 자동으로 구성되게 만듭니다.

### 여백 40% 규칙의 MVP 해석

MoSCoW에는 "여백 비율 40% 이상"이라는 표현이 있습니다.

MVP에서는 이를 픽셀 단위 알고리즘으로 계산하기보다 디자인 규칙으로 해석합니다.

적용 규칙:

- 섹션 상하 padding을 충분히 둡니다.
- 텍스트 최대 폭을 제한합니다.
- 한 섹션에 너무 많은 요소를 넣지 않습니다.
- 제목과 본문 사이의 간격을 고정합니다.
- 이미지 주변 margin을 확보합니다.
- 카드형 UI를 과도하게 남발하지 않습니다.
- 제목, 본문, 보조 문구의 위계를 명확히 합니다.

이렇게 하면 복잡한 시각 분석 없이도 "숨 쉴 공간이 있는 상세페이지"를 만들 수 있습니다.

### 사용자 입력 UI

이 기능 역시 텍스트 입력보다 선택형 UI가 적합합니다.

디자인 무드 선택:

- 미니멀
- 감성
- 프리미엄
- 정보형
- 공구형

이미지 중심도 선택:

- 이미지 크게
- 이미지/텍스트 균형
- 정보 설명 강조

상세페이지 분위기 선택:

- 차분한
- 따뜻한
- 세련된
- 실용적인

강조 방식 선택:

- 첫 화면 임팩트
- 장점 3개 강조
- 사용 장면 강조
- FAQ/신뢰 요소 강조

### 기획 관점 정리

이 기능의 본질은 Pinterest API가 아니라 디자인 감도를 자동화하는 것입니다.

기획자가 이해하기 쉬운 표현:

"MVP에서는 외부 Pinterest 이미지를 실시간으로 가져오는 대신, Pinterest 감성의 디자인 원칙을 내부 무드 프리셋으로 구현한다. 이를 통해 API/저작권/레퍼런스 품질 이슈 없이도 사용자는 감도 있는 상세페이지 초안을 빠르게 얻을 수 있다."

### 사업화 확장 방향

MVP가 완성된 뒤 다음 단계에서 Pinterest 연동을 확장할 수 있습니다.

확장 단계:

1. 내부 무드 프리셋으로 MVP 검증
2. 사용자 선호 무드 데이터 수집
3. 실제 Pinterest API 또는 레퍼런스 수집 기능 검토
4. 레퍼런스 이미지의 색상, 여백, 구도 분석
5. 내 상품 이미지와 레퍼런스 무드 매칭
6. 이미지 합성 또는 고급 레이아웃 추천으로 확장

즉, Pinterest 연동은 MVP 필수 기능이 아니라 사업화 단계의 고도화 기능입니다.

## M-04: 데스크톱 기반 블록 순서 편집기

### 기존 아이디어

기존 요구사항은 "모바일 퍼스트 WYSIWYG 드래그 앤 드롭 편집기"였습니다.

여기서 모바일 퍼스트는 셀러가 모바일에서 편집한다는 뜻이 아닙니다.

정확한 의미:

- 셀러는 PC/노트북에서 서비스를 사용합니다.
- 편집 화면 안에 모바일 상세페이지 비율의 세로 캔버스를 보여줍니다.
- 최종 결과물은 모바일 쇼핑 상세페이지에 최적화된 긴 세로 이미지입니다.

### 논의 결과

MVP의 편집기는 피그마처럼 자유롭게 모든 요소를 움직이는 도구가 아닙니다.

`dnd-kit`을 사용하면 높은 수준의 드래그 인터랙션을 만들 수 있지만, 중요한 것은 드래그 가능 범위를 제한하는 것입니다.

허용할 드래그:

- 섹션 블록 단위 순서 변경
- 13대 상세페이지 영역의 위/아래 재배치

허용하지 않을 드래그:

- 텍스트 박스 자유 좌표 이동
- 이미지 레이어 자유 배치
- 섹션 내부 요소 리사이즈
- 피그마/캔바식 레이어 편집

### 기능명 수정 제안

기존 이름:

- 직관적인 드래그 앤 드롭 블록 순서 편집기

MVP 이름:

- 데스크톱 기반 블록 순서 편집기

### 구현 방향

사용자는 PC 화면에서 모바일 상세페이지 캔버스를 보며 섹션 흐름을 조정합니다.

MVP에서는 다음 기능을 제공합니다.

- `dnd-kit` 기반 섹션 블록 재정렬
- 드래그 핸들을 잡았을 때만 블록 이동
- 섹션 클릭 시 편집 패널 열기
- 섹션 숨김/삭제
- 숨긴 섹션 복구

드래그 핸들을 별도로 두는 이유:

- 텍스트 클릭 편집과 드래그가 충돌하지 않게 하기 위해서입니다.
- 이미지 교체, 버튼 클릭, 텍스트 선택 중 의도치 않게 블록이 움직이는 문제를 줄입니다.
- 데스크톱 사용 환경에서 더 명확한 조작감을 제공합니다.

### 기획 관점 정리

이 기능은 자유 디자인 기능이 아니라 상세페이지 흐름 편집 기능입니다.

기획자가 이해하기 쉬운 표현:

"AI가 생성한 상세페이지 섹션을 사용자가 판매 전략에 맞게 재정렬하는 기능입니다. 자유 배치가 아니라 섹션 단위 흐름 조정만 제공해 디자인 품질을 유지합니다."

## M-05: 플랫폼 업로드용 슬라이싱 ZIP 다운로드

### 기존 아이디어

기존 요구사항은 "멀티 플랫폼 규격 매핑 및 고화질 자동 슬라이싱 내보내기"였습니다.

완성된 상세페이지를 플랫폼별 권장 가로폭에 맞추고, 너무 긴 세로 이미지를 일정 단위로 잘라 파일 패키지로 제공하는 기능입니다.

### 논의 결과

기존 셀러들도 긴 상세페이지 이미지를 여러 개의 이미지로 잘라 업로드하는 방식을 자주 사용합니다.

이유:

- 한 장이 너무 길면 업로드 실패 가능성이 있습니다.
- 이미지 용량이 커져 로딩이 느려질 수 있습니다.
- 플랫폼별 이미지 용량/해상도 제한에 걸릴 수 있습니다.
- 중간 섹션만 수정할 때 전체 이미지를 다시 올리지 않아도 됩니다.
- 모바일에서는 여러 이미지를 순서대로 업로드해도 사용자에게는 이어진 상세페이지처럼 보입니다.

따라서 이 기능은 셀러가 포토샵이나 피그마에서 수동으로 하던 "자르기, 파일명 정리, 압축" 과정을 자동화하는 기능입니다.

### MVP 구현 방향

MVP에서는 플랫폼 업로드용 이미지 패키지를 ZIP으로 다운로드하는 흐름을 목표로 합니다.

기본 흐름:

1. 사용자가 상세페이지를 완성합니다.
2. 플랫폼을 선택합니다.
3. 앱이 전체 상세페이지를 플랫폼 가로폭 기준으로 렌더링합니다.
4. 상세페이지 이미지를 세로 2000px 단위로 자릅니다.
5. 잘린 이미지 파일을 `01.png`, `02.png`, `03.png`처럼 넘버링합니다.
6. 잘린 이미지들을 하나의 ZIP 파일로 묶습니다.
7. 사용자는 ZIP 파일을 다운로드합니다.
8. 압축을 풀고 쇼핑몰 관리자에 순서대로 업로드합니다.

예시:

전체 상세페이지가 860px x 7300px인 경우:

- `01.png`: 860px x 2000px
- `02.png`: 860px x 2000px
- `03.png`: 860px x 2000px
- `04.png`: 860px x 1300px

### 플랫폼 규격

MVP 우선 지원:

- 에이블리: 860px
- 지그재그: 1000px

추후 확장:

- 스마트스토어
- 쿠팡
- 카페24
- 사용자 지정 가로폭

### 2000px 슬라이싱 기준

2000px은 긴 상세페이지를 안정적으로 나누기 위한 기본값입니다.

단, 모든 셀러가 반드시 2000px로 자르는 것은 아닙니다. 일부는 섹션 기준으로 자르거나 1500-3000px 범위에서 나누기도 합니다.

MVP에서는 2000px 고정값으로 단순화하고, 추후 다음 옵션을 검토합니다.

- 1500px 단위
- 2000px 단위
- 3000px 단위
- 섹션별 슬라이싱

### 외부 캡처 도구 검토

Awesome Screenshot 같은 브라우저 확장 프로그램은 발표 자료 제작이나 내부 테스트용 보조 도구로 사용할 수 있습니다.

하지만 최종 서비스의 내보내기 기능으로 의존하기에는 적합하지 않습니다.

이유:

- 사용자가 확장 프로그램을 별도로 설치해야 합니다.
- 플랫폼별 가로폭을 정확히 보장하기 어렵습니다.
- 2000px 단위 슬라이싱과 파일명 정리를 자동화하기 어렵습니다.
- ZIP 패키징까지 서비스 내부에서 보장하기 어렵습니다.
- 사용자의 브라우저 배율, 스크롤 상태, 확장 권한에 따라 결과물이 달라질 수 있습니다.

따라서 외부 캡처 도구는 개발/발표 보조 수단으로만 사용하고, 제품 기능은 자체 내보내기 엔진으로 구현합니다.

### 기획 관점 정리

기능명은 단순한 "다운로드"보다 "플랫폼 업로드용 이미지 패키지 다운로드"가 적합합니다.

기획자가 이해하기 쉬운 표현:

"기존 셀러들이 포토샵에서 수동으로 하던 상세페이지 자르기와 파일 정리를 자동화합니다. 완성된 상세페이지를 플랫폼 권장 가로폭에 맞춘 뒤 2000px 단위로 나누고, 순서가 정리된 이미지 파일을 ZIP으로 제공합니다."

## M-06: 업로드 이미지 자동 최적화

### 기존 아이디어

기존 요구사항은 "클라이언트 측 고해상도 이미지 선압축 가공(WebP)"이었습니다.

사용자가 아이폰, DSLR 등으로 촬영한 고해상도 원본 이미지를 그대로 업로드하면 브라우저가 느려지거나 캔버스 렌더링, 이미지 다운로드, ZIP 슬라이싱 과정에서 메모리 부담이 커질 수 있습니다.

### 논의 결과

MVP에서는 복잡한 이미지 처리 옵션을 제공하지 않고, 업로드 직후 브라우저에서 자동 최적화하는 방식으로 확정합니다.

목적은 이미지 품질 개선이 아니라 브라우저 안정성과 편집 성능 확보입니다.

### MVP 확정안

- 업로드 이미지 최대 가로폭: 1200px
- 출력 포맷: WebP 우선, 브라우저 호환 문제가 있으면 JPEG
- 압축 품질: 0.85
- 원본 용량이 큰 경우 자동 압축
- 최적화 후 사용자에게 상태 표시

상태 표시 예시:

- "이미지를 최적화했습니다."
- "8.4MB -> 1.2MB"
- "가로 3024px -> 1200px"

### 구현 흐름

1. 사용자가 이미지를 업로드합니다.
2. 브라우저에서 이미지 크기와 용량을 확인합니다.
3. 가로폭이 1200px보다 크면 원본 비율을 유지해 리사이즈합니다.
4. Canvas에 이미지를 다시 그립니다.
5. `canvas.toBlob()`으로 WebP 또는 JPEG 파일을 생성합니다.
6. 압축된 Blob을 미리보기, 캔버스, 다운로드 기능에 사용합니다.
7. 압축 결과를 UI에 표시합니다.

### MVP에서 하지 않는 것

- 원본 이미지 장기 보관
- 고급 이미지 보정
- 누끼 제거
- AI 배경 합성
- 카테고리별 세밀한 압축률 조정
- 데스크톱 앱 기반 대량 이미지 처리

원본 품질 보존은 MVP 필수 기능이 아닙니다.

이 툴의 목적은 인쇄용 원본 관리가 아니라 쇼핑몰 상세페이지용 웹 이미지 제작이기 때문입니다.

### 추후 옵션

고가 제품이나 디테일이 중요한 카테고리를 위해 추후 다음 옵션을 검토할 수 있습니다.

- 일반 최적화: 1200px / 0.85
- 고화질 최적화: 1600px / 0.9
- 원본 보관 옵션
- 이미지별 압축률 수동 조정

### Electron/Tauri 검토

Electron 또는 Tauri 같은 데스크톱 앱으로 만들면 로컬 파일 처리와 대용량 이미지 가공은 웹앱보다 유리합니다.

가능해지는 것:

- 원본 이미지를 로컬 폴더에서 직접 읽기
- Sharp 같은 Node.js 이미지 처리 라이브러리 사용
- 큰 상세페이지 이미지를 더 안정적으로 슬라이싱
- ZIP 파일을 원하는 폴더에 바로 저장
- 여러 이미지 일괄 처리
- 브라우저 CORS 문제 회피

하지만 Electron도 내부 렌더링은 Chromium 기반이므로 메모리 문제가 완전히 사라지는 것은 아닙니다.

특히 UI 렌더러에서 큰 Canvas와 이미지를 직접 다루면 여전히 성능 문제가 생길 수 있습니다.

MVP에서는 접근성과 배포가 쉬운 웹앱으로 구현합니다.

대량 이미지 처리, 고해상도 로컬 내보내기, 폴더 단위 작업이 중요해지는 사업화 단계에서 Electron/Tauri 전환을 검토합니다.

### 기획 관점 정리

기능명은 "고해상도 이미지 선압축"보다 "업로드 이미지 자동 최적화"가 사용자 친화적입니다.

기획자가 이해하기 쉬운 표현:

"사용자가 고해상도 원본 사진을 올리더라도 브라우저가 느려지지 않도록, 업로드 직후 이미지를 상세페이지 제작에 적합한 크기와 용량으로 자동 최적화합니다."

## 임시 결론

MVP의 핵심은 자유로운 디자인 툴이 아니라 구조화된 상세페이지 생성 및 편집 흐름입니다.

현재 우선순위:

1. 블록형 모바일 WYSIWYG 에디터
2. 13대 섹션 데이터 구조
3. 최소 입력 + 선택형 UI
4. 구조화된 AI JSON 출력
5. 낮은 temperature와 출력 검증을 통한 허위 정보 억제
6. 무드 프리셋 기반 레이아웃 자동 매칭
7. 데스크톱 기반 블록 순서 편집
8. 플랫폼 업로드용 슬라이싱 ZIP 다운로드
9. 업로드 이미지 자동 최적화
