## 프롬프트

```txt
너는 웹 애플리케이션 UI/UX 디자이너이자 프론트엔드 설계자야.

연결된 GitHub repo를 참고해서 Next.js + TypeScript + Tailwind CSS + shadcn/ui 구조에 맞는 UI 초안을 만들어줘.

서비스 개요:
이 서비스는 커머스 셀러가 상품 정보와 이미지를 입력하면 AI가 상세페이지 초안을 만들고, 사용자가 데스크톱에서 모바일 상세페이지 캔버스를 보며 블록 단위로 수정한 뒤 플랫폼 업로드용 이미지 ZIP을 다운로드하는 웹 애플리케이션이야.

중요:
- 사용자는 PC/노트북에서 작업한다.
- 결과물 미리보기는 모바일 상세페이지 형태의 긴 세로 캔버스다.
- 세로로 긴 상세페이지를 작업하는 툴이므로 세로 모니터를 사용하는 셀러도 편하게 사용할 수 있어야 한다.
- 현재 MVP는 피그마/캔바 같은 자유 디자인 툴이 아니다.
- 현재 MVP는 섹션 블록 단위로 편집하는 AI 상세페이지 편집기다.
- 다만 캔버스, 섹션, 텍스트, 이미지 컴포넌트 구조는 나중에 더 세밀한 편집 기능으로 확장될 수 있게 설계한다.

기술 전제:
- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- lucide-react
- dnd-kit
- Supabase
- Vercel AI SDK
- JSZip

디자인할 화면:
1. 로그인/회원가입
2. 프로젝트 대시보드
3. 새 상세페이지 생성
4. 상세페이지 편집기
5. 스타일 세트 관리
6. 관리자 화면

전체 디자인 방향:
- 실무용 웹 앱처럼 차분하고 명확하게
- 과한 랜딩페이지 느낌 금지
- 장식보다 작업 흐름을 우선
- 정보가 많은 화면도 정돈된 밀도로 구성
- 카드 중첩을 과하게 사용하지 말 것
- 아이콘은 lucide-react 기준으로 제안
- 일반 노트북, 가로 모니터, 세로 모니터에서 모두 작업 가능한 반응형 구조로 제안
```

## 디자인 레퍼런스 방향

```txt
아래 디자인 레퍼런스는 특정 브랜드를 복제하기 위한 것이 아니다.
색상, 타이포그래피, 간격, 정보 밀도, 컴포넌트 구성 원칙만 참고한다.

참고 사이트:
https://getdesign.md/

참고하고 싶은 방향:
- Linear: 정돈된 SaaS 대시보드, 빠른 작업 흐름, 낮은 장식성
- Shopify: 커머스 운영 도구의 신뢰감, 상품/주문/설정 관리에 적합한 구조
- Notion: 부담 없는 작업 화면, 부드러운 표면, 문서/블록 기반 편집 감각
- Vercel: 간결한 개발자 도구 느낌, 명확한 타이포그래피와 여백
- Claude: AI 생성/수정 경험의 차분한 톤, 따뜻하지만 정돈된 작업 화면

주의:
- 브랜드 UI를 그대로 베끼지 말 것
- 특정 브랜드의 고유한 로고, 색상 조합, 카피, 레이아웃을 복제하지 말 것
- 이 프로젝트에 맞는 독립적인 디자인 시스템으로 재해석할 것
- 보라색/남색 그라데이션 중심의 일반적인 AI 툴 느낌은 피할 것
- 이미지 큐레이션 서비스처럼 보이지 않게 하고, 셀러가 매일 쓰는 커머스 AI 작업 도구처럼 보이게 할 것
```

## 화면별 요구사항

### 1. 로그인/회원가입

```txt
필수 요소:
- 서비스명
- 이메일 입력
- 비밀번호 입력
- 로그인 버튼
- 회원가입 전환
- 데모 계정 진입 버튼

방향:
- 업무 도구에 들어가는 첫 화면처럼 단정하게 구성
- 과한 일러스트나 추상 배경은 사용하지 않음
```

### 2. 프로젝트 대시보드

```txt
필수 요소:
- 상단 네비게이션
- 새 상세페이지 만들기 버튼
- 프로젝트 검색
- 프로젝트 리스트
- 상품명, 카테고리, 플랫폼, 수정일 표시
- 스타일 세트 바로가기

방향:
- 프로젝트가 늘어나도 관리하기 쉬운 리스트/테이블 중심
- 다음 행동이 명확해야 함
```

### 3. 새 상세페이지 생성

```txt
필수 요소:
- 상품명
- 카테고리
- 핵심 키워드
- 타깃 고객
- 상품 이미지 업로드
- 톤앤매너 선택
- 디자인 무드 선택
- 강조 포인트 체크박스
- 플랫폼 선택
- 스타일 세트 선택
- AI 생성 버튼

UI 방향:
- 모든 항목을 텍스트 입력으로 만들지 말 것
- 선택형 UI, 체크박스, 토글, 칩을 적극 사용
- 이미지 최적화 상태를 표시
- 입력 부담이 적어 보이게 섹션을 나눔
```

### 4. 상세페이지 편집기

```txt
가장 중요한 화면이므로 가장 구체적으로 설계해줘.

핵심 구조:
- 데스크톱 작업 화면
- 모바일 상세페이지 캔버스
- 섹션 목록
- 선택 섹션 편집 패널
- 상단 작업 바

반응형 작업 환경:
- 가로 모니터에서는 섹션 목록, 모바일 캔버스, 선택 섹션 편집 패널을 함께 보는 3열 구조를 우선 제안
- 세로 모니터에서는 긴 모바일 캔버스가 화면의 중심이 되도록 제안
- 세로 모니터에서는 섹션 목록과 편집 패널을 상단/하단 패널, 접이식 사이드 패널, 탭 패널 중 하나로 전환
- 캔버스와 보조 패널은 독립 스크롤이 가능해야 함
- 상단 작업 바의 저장, 플랫폼 선택, 다운로드 버튼은 화면 비율이 바뀌어도 접근 가능해야 함
- 텍스트, 버튼, 패널이 겹치지 않아야 함

모바일 캔버스:
- 긴 세로형 상세페이지
- 13개 섹션 표시
- 선택된 섹션 하이라이트
- 실제 export 결과와 유사한 비율
- 세로 모니터에서는 캔버스가 충분히 크게 보이고, 스크롤 흐름이 자연스러워야 함

13개 섹션:
1. Intro
2. One Line Selling Point
3. Problem
4. Solution
5. Key Benefit 1
6. Key Benefit 2
7. Key Benefit 3
8. Detail Point
9. Use Scene
10. Recommended For
11. Trust Point
12. FAQ
13. CTA

편집 기능:
- 문구 수정
- 이미지 교체
- 섹션 숨김/복구
- 섹션 순서 변경
- 카피 후보 선택
- 특정 섹션 다시 생성

상단 작업:
- 저장
- 미리보기
- 플랫폼 선택
- 전체 PNG 다운로드
- 슬라이싱 ZIP 다운로드

금지:
- MVP 화면에서 자유 좌표 편집을 핵심 기능처럼 보이게 만들지 말 것
- MVP 화면에서 임의 텍스트 박스 생성 기능을 제공하지 말 것
- MVP 화면에서 레이어 패널을 제공하지 말 것
- MVP 화면에서 자유 드로잉 도구를 제공하지 말 것

확장 가능성:
- 현재는 블록형 편집기를 우선한다.
- 단, 캔버스/섹션/텍스트/이미지 컴포넌트는 나중에 더 세밀한 위치 조정이나 자유 편집으로 확장될 수 있게 분리된 구조로 제안한다.
- UI는 단순하게 유지하되 내부 컴포넌트 구조는 너무 닫히지 않게 설계한다.
```

