## 프롬프트

```txt
너는 웹 애플리케이션 UI/UX 디자이너이자 프론트엔드 설계자야.

연결된 GitHub repo를 참고해서 Next.js + TypeScript + Tailwind CSS + shadcn/ui 구조에 맞는 UI 초안을 만들어줘.

서비스 개요:
이 서비스는 커머스 셀러가 상품 정보와 이미지를 입력하면 AI가 상세페이지 초안을 만들고, 사용자가 데스크톱에서 모바일 상세페이지 캔버스를 보며 블록 단위로 수정한 뒤 플랫폼 업로드용 이미지 ZIP을 다운로드하는 웹 애플리케이션이야.
사용자가 직접 모든 문구를 고치기 귀찮을 수 있으므로, 편집기 안에는 선택 섹션을 바로 수정해주는 AI 편집 도우미 패널이 있어야 해.
도매 사이트에서 가져온 낮은 퀄리티의 상품 이미지를 레퍼런스 이미지의 구도, 조명, 배경 분위기를 참고해 상세페이지에 어울리는 이미지로 개선/합성하는 흐름도 핵심이야.

중요:
- 사용자는 PC/노트북에서 작업한다.
- 결과물 미리보기는 모바일 상세페이지 형태의 긴 세로 캔버스다.
- 세로로 긴 상세페이지를 작업하는 툴이므로 세로 모니터를 사용하는 셀러도 편하게 사용할 수 있어야 한다.
- 앱 UI는 light/dark 모드를 지원해야 한다.
- 단, 상세페이지 캔버스와 export 결과물은 앱 테마와 분리되어야 한다.
- 현재 MVP는 피그마/캔바 같은 자유 디자인 툴이 아니다.
- 현재 MVP는 섹션 블록 단위로 편집하는 AI 상세페이지 편집기다.
- 다만 캔버스, 섹션, 텍스트, 이미지 컴포넌트 구조는 나중에 더 세밀한 편집 기능으로 확장될 수 있게 설계한다.
- AI 편집 도우미는 현재는 편집기 보조 패널이지만, 구조적으로는 나중에 상세페이지 작업 전체를 조율하는 상위 AI 에이전트로 확장될 수 있게 설계한다.

기술 전제:
- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- lucide-react
- dnd-kit
- Supabase
- Vercel AI SDK
- JSZip
- next-themes 또는 동등한 테마 관리 방식
- GSAP
- @gsap/react

디자인할 화면:
1. 로그인/회원가입
2. 프로젝트 대시보드
3. 새 상세페이지 생성
4. 상세페이지 편집기
5. 스타일 세트 관리
6. 관리자 화면

전체 디자인 방향:
- 실무용 웹 앱처럼 차분하고 명확하게
- 과한 랜딩페이지 느낌 금지
- 장식보다 작업 흐름을 우선
- 정보가 많은 화면도 정돈된 밀도로 구성
- 카드 중첩을 과하게 사용하지 말 것
- 아이콘은 lucide-react 기준으로 제안
- 일반 노트북, 가로 모니터, 세로 모니터에서 모두 작업 가능한 반응형 구조로 제안
- light/dark 테마를 모두 고려한 색상 토큰과 컴포넌트 상태를 제안
- GSAP은 모든 화면을 화려하게 만드는 용도가 아니라 AI 도우미 진입, 결과 적용, export 완료 같은 핵심 순간에만 사용
```

## 디자인 레퍼런스 방향

```txt
아래 디자인 레퍼런스는 특정 브랜드를 복제하기 위한 것이 아니다.
색상, 타이포그래피, 간격, 정보 밀도, 컴포넌트 구성 원칙만 참고한다.

참고 사이트:
https://getdesign.md/

레퍼런스 우선순위:
- Claude 50%: 전체 톤, AI 생성/수정 경험, 문장을 읽고 고치는 작업 화면
- Shopify 20%: 커머스 운영 도구의 신뢰감, 상품/설정 관리에 적합한 구조
- Linear 15%: 정돈된 SaaS 대시보드, 빠른 작업 흐름, 낮은 장식성
- Notion 10%: 부담 없는 작업 화면, 부드러운 표면, 블록 기반 편집 감각
- Vercel 5%: 간결한 개발자 도구 느낌, 명확한 타이포그래피와 여백

가장 강하게 반영할 방향:
- Claude의 따뜻한 뉴트럴 톤
- AI가 만든 문구를 편하게 읽고 수정하는 경험
- 과하게 번쩍이는 AI 툴 느낌보다 조용하고 신뢰감 있는 작업 화면
- 긴 문장과 섹션을 오래 검토해도 피로하지 않은 대비와 간격
- 사용자가 직접 타이핑해서 고치기보다 AI에게 짧게 요청하고 결과를 바로 반영하는 경험

주의:
- 브랜드 UI를 그대로 베끼지 말 것
- 특정 브랜드의 고유한 로고, 색상 조합, 카피, 레이아웃을 복제하지 말 것
- 이 프로젝트에 맞는 독립적인 디자인 시스템으로 재해석할 것
- 보라색/남색 그라데이션 중심의 일반적인 AI 툴 느낌은 피할 것
- 이미지 큐레이션 서비스처럼 보이지 않게 하고, 셀러가 매일 쓰는 커머스 AI 작업 도구처럼 보이게 할 것
```

## 테마 요구사항

```txt
light/dark 모드를 모두 설계해줘.

필수:
- light/dark/system 선택 UI
- 상단 네비게이션 또는 사용자 메뉴의 테마 토글
- 대시보드, 편집기, 관리자 화면 모두에서 충분한 대비
- 입력 폼, 테이블, 탭, 배지, 버튼, 패널의 dark mode 상태
- hover, selected, disabled, loading 상태의 테마별 표현

중요:
- 앱 UI의 테마와 상세페이지 캔버스의 최종 결과물 테마를 분리해야 함
- 예를 들어 앱이 dark mode여도 상세페이지 캔버스는 사용자가 선택한 디자인 무드와 스타일 세트를 유지해야 함
- export PNG/ZIP 결과물은 앱의 light/dark 모드에 영향을 받지 않아야 함
```

### 4. 상세페이지 편집기

```txt
가장 중요한 화면이므로 가장 구체적으로 설계해줘.

핵심 구조:
- 데스크톱 작업 화면
- 모바일 상세페이지 캔버스
- 섹션 목록
- 선택 섹션 편집 패널
- AI 편집 도우미 패널
- 상단 작업 바
- 테마 토글 또는 사용자 메뉴

반응형 작업 환경:
- 가로 모니터에서는 섹션 목록, 모바일 캔버스, 선택 섹션 편집 패널을 함께 보는 3열 구조를 우선 제안
- 세로 모니터에서는 긴 모바일 캔버스가 화면의 중심이 되도록 제안
- 세로 모니터에서는 섹션 목록과 편집 패널을 상단/하단 패널, 접이식 사이드 패널, 탭 패널 중 하나로 전환
- 캔버스와 보조 패널은 독립 스크롤이 가능해야 함
- 상단 작업 바의 저장, 플랫폼 선택, 다운로드 버튼은 화면 비율이 바뀌어도 접근 가능해야 함
- 텍스트, 버튼, 패널이 겹치지 않아야 함

모바일 캔버스:
- 긴 세로형 상세페이지
- 13개 섹션 표시
- 선택된 섹션 하이라이트
- 실제 export 결과와 유사한 비율
- 세로 모니터에서는 캔버스가 충분히 크게 보이고, 스크롤 흐름이 자연스러워야 함

13개 섹션:
1. Intro
2. One Line Selling Point
3. Problem
4. Solution
5. Key Benefit 1
6. Key Benefit 2
7. Key Benefit 3
8. Detail Point
9. Use Scene
10. Recommended For
11. Trust Point
12. FAQ
13. CTA

편집 기능:
- 문구 수정
- 이미지 교체
- 섹션 숨김/복구
- 섹션 순서 변경
- 카피 후보 선택
- 특정 섹션 다시 생성

AI 편집 도우미:
- 선택된 섹션을 기준으로 동작
- 빠른 액션 버튼 제공
- "짧게 줄이기"
- "차분한 톤으로 바꾸기"
- "프리미엄 톤으로 바꾸기"
- "과장 표현 검토"
- "FAQ 다시 쓰기"
- "CTA 다시 쓰기"
- 짧은 자유 입력 제공
- 결과는 채팅 답변으로만 끝나지 않고 적용하기 버튼으로 섹션에 반영 가능해야 함
- 적용 전/후 비교가 가능해야 함
- API 비용을 줄이기 위해 전체 상세페이지 재생성이 아니라 섹션 단위 수정처럼 보이게 설계
- 나중에 저장, 검수, export 준비 같은 내부 기능을 조율하는 상위 AI 에이전트로 확장될 수 있는 구조를 제안

AI 도우미 인터랙션:
- floating AI 도우미 아이콘을 제공
- 아이콘은 작고 방해되지 않지만 눈에 띄어야 함
- 클릭하면 원형 버튼이 부드럽게 확장되어 floating 패널 또는 채팅형 도우미로 열리는 인터랙션을 제안
- 이 인터랙션은 GSAP으로 구현하기 좋은 구조로 제안
- 패널이 열릴 때 배경이나 캔버스를 과하게 가리지 않도록 설계
- prefers-reduced-motion 설정을 고려

상단 작업:
- 저장
- 미리보기
- 플랫폼 선택
- 전체 PNG 다운로드
- 슬라이싱 ZIP 다운로드

금지:
- MVP 화면에서 자유 좌표 편집을 핵심 기능처럼 보이게 만들지 말 것
- MVP 화면에서 임의 텍스트 박스 생성 기능을 제공하지 말 것
- MVP 화면에서 레이어 패널을 제공하지 말 것
- MVP 화면에서 자유 드로잉 도구를 제공하지 말 것

확장 가능성:
- 현재는 블록형 편집기를 우선한다.
- 단, 캔버스/섹션/텍스트/이미지 컴포넌트는 나중에 더 세밀한 위치 조정이나 자유 편집으로 확장될 수 있게 분리된 구조로 제안한다.
- UI는 단순하게 유지하되 내부 컴포넌트 구조는 너무 닫히지 않게 설계한다.
```
