# MVP Plan

## 목표

상품 정보, 이미지, 경쟁 상세페이지 URL/메모를 입력하면 AI 에이전트가 분석, 기획, 제작, 검수를 단계별로 수행하고, 사용자는 데스크톱 화면에서 모바일 상세페이지 캔버스를 보며 필요한 부분만 간단히 수정한 뒤, 플랫폼 업로드용 이미지 ZIP을 다운로드할 수 있습니다.

이 프로젝트는 수업 미니 프로젝트로 진행하며, 현재 구현 범위 안에서 완성도 있는 결과물을 만드는 데 집중합니다.

## 핵심 사용자

- 쿠팡, 네이버 스마트스토어, 에이블리, 지그재그 등에 상품을 등록하는 셀러
- 상세페이지 문구와 구성을 직접 만들기 어려운 초보 셀러
- 디자인 툴 없이 빠르게 상세페이지 초안을 만들고 싶은 사용자
- 세로로 긴 상세페이지를 편하게 보기 위해 세로 모니터를 사용하는 사용자

## 핵심 플로우

1. 사용자가 로그인합니다.
2. 새 상세페이지 프로젝트를 생성합니다.
3. 상품명, 카테고리, 키워드, 타깃 고객, 강조 포인트를 입력합니다.
4. 경쟁 상세페이지 URL과 참고 메모를 입력합니다.
5. 상품 이미지를 업로드합니다.
6. 레퍼런스 이미지 또는 디자인 무드를 선택합니다.
7. 분석 에이전트가 사용자가 제공한 URL/메모를 바탕으로 경쟁 셀러의 구성, 셀링포인트, 표현 톤을 정리합니다.
8. 기획 에이전트가 분석 결과와 상품 정보를 바탕으로 상세페이지 전략을 만듭니다.
9. 제작 에이전트가 13개 섹션 상세페이지 초안을 생성합니다.
10. 검수 에이전트가 과장 표현, 근거 없는 수치/인증, 누락 섹션, 모바일 가독성을 점검합니다.
11. 사용자가 모바일 캔버스에서 상세페이지를 확인합니다.
12. 수정이 필요하면 사용자가 기획자 에이전트에게 수정 요청을 남깁니다.
13. 기획자 에이전트가 요청을 반영해 재기획하고, 제작/검수 에이전트가 새 시안을 제출합니다.
14. 사용자가 섹션 문구, 이미지, 순서, 숨김 여부를 간단히 수동 수정할 수 있습니다.
15. 사용자의 수동 수정 내용과 스타일 선호를 저장합니다.
16. 작업물을 저장합니다.
17. 플랫폼 규격에 맞춰 이미지를 슬라이싱하고 ZIP으로 다운로드합니다.

## Must Have

### 1. 인증

- 이메일/비밀번호 회원가입
- 이메일/비밀번호 로그인
- 데모 계정 로그인 진입
- 로그아웃
- 로그인한 사용자 기준 프로젝트 조회

### 2. 프로젝트 대시보드

- 저장된 상세페이지 프로젝트 목록
- 새 프로젝트 만들기
- 프로젝트명, 카테고리, 플랫폼, 수정일 표시
- 프로젝트 다시 열기

### 3. 상품 정보 입력

- 상품명
- 카테고리
- 핵심 키워드
- 타깃 고객
- 강조 포인트 체크박스
- 톤앤매너 선택
- 디자인 무드 선택
- 플랫폼 선택
- 추가 제작 요청 입력
- 경쟁 상세페이지 URL 입력
- 경쟁 상세페이지 참고 메모 입력

입력 UI는 텍스트 입력만 사용하지 않고, 선택형 UI를 적극적으로 사용합니다.
추가 제작 요청은 필수 입력값이 아니라 선택 입력값으로 둡니다. 사용자는 "프리미엄 브랜드몰처럼", "공구 느낌은 줄이고 담백하게", "첫 화면은 이미지 중심으로"처럼 AI가 초안을 만들 때 참고할 방향만 짧게 적을 수 있습니다.

경쟁 상세페이지 URL은 사용자가 직접 입력한 참고 링크로만 사용합니다. MVP에서는 외부 사이트의 HTML, 이미지, 리뷰를 자동 크롤링하지 않습니다. 사용자는 URL과 함께 "첫 화면이 좋음", "FAQ 구성이 참고됨", "색감은 별로임" 같은 짧은 메모를 남길 수 있고, 분석 에이전트는 이 메모와 상품 정보를 바탕으로 경쟁 분석 초안을 만듭니다.

### 3-1. 에이전트 워크플로우

MVP의 AI 생성은 단일 호출로 끝나는 문구 생성기가 아니라, 단계별 에이전트 결과물을 쌓는 흐름으로 설계합니다.

#### 분석 에이전트

- 입력: 상품 정보, 경쟁 상세페이지 URL 목록, 사용자가 남긴 참고 메모
- 출력: 경쟁 셀러의 예상 구성, 주요 셀링포인트, 표현 톤, 참고할 점, 피해야 할 점
- 제한: 외부 사이트 자동 크롤링 없음, 사용자가 제공하지 않은 경쟁사 원문/이미지 내용 단정 금지

#### 기획 에이전트

- 입력: 상품 정보, 분석 에이전트 결과, 사용자 스타일 세트, 이전 수동 수정 경향
- 출력: 상세페이지 전략, 섹션별 역할, 강조 순서, 톤앤매너, 이미지 방향
- 목표: "무엇을 어떤 순서로 보여줄지"를 먼저 정리해서 제작 결과의 일관성을 높임

#### 제작 에이전트

- 입력: 기획안, 상품 정보, 이미지 설명, 추가 제작 요청
- 출력: 13개 섹션 JSON, 섹션별 카피, 상세설명, 이미지 역할, 이미지 프롬프트
- 현재 구현된 AI 상세페이지 생성 API는 이 제작 에이전트 역할부터 시작합니다.

#### 검수 에이전트

- 입력: 제작 에이전트 결과, 상품 정보, 플랫폼, 금지 표현 규칙
- 출력: 검수 점수, 경고 목록, 수정 제안, 자동 수정 가능 여부
- 검수 기준: 과장 표현, 근거 없는 효능/인증/수치, 섹션 누락, 모바일 가독성, CTA 명확성

#### 수정 요청 루프

- 별도의 편집 에이전트는 두지 않습니다.
- 사용자가 "더 프리미엄하게", "첫 화면을 이미지 중심으로", "FAQ를 줄여줘"처럼 수정 요청을 남기면 기획자 에이전트가 기존 분석/기획/검수 결과를 바탕으로 재기획합니다.
- 재기획 결과는 제작 에이전트와 검수 에이전트를 다시 거쳐 새 시안으로 제출됩니다.
- 사용자는 새 시안을 확인한 뒤 필요한 부분만 간단히 수동 수정하고 내보내기합니다.

### 4. 이미지 업로드 및 최적화

- 상품 이미지 업로드
- 레퍼런스 이미지 업로드 또는 레퍼런스 메모 입력
- 업로드 이미지 최대 가로폭 1200px로 리사이즈
- WebP 우선, 필요 시 JPEG 사용
- 품질 0.85 기준 압축
- 최적화 전/후 용량 표시
- 최적화 완료 상태 표시

### 5. 레퍼런스 기반 이미지 개선 플로우

도매 사이트에서 가져온 낮은 퀄리티의 상품 이미지를 상세페이지에 어울리는 이미지로 다듬기 위한 흐름을 제공합니다.

목표:

- 원본 상품 이미지를 상세페이지용 이미지로 개선합니다.
- 레퍼런스 이미지의 구도, 조명, 배경 분위기, 색감만 참고합니다.
- 실제 상품의 형태, 색상, 소재, 구성품은 임의로 바꾸지 않습니다.
- 개선된 이미지를 상세페이지 섹션에 바로 배치할 수 있게 합니다.

MVP 범위:

- 원본 상품 이미지 표시
- 레퍼런스 이미지 표시
- 이미지 개선 방향 요약
- 이미지 생성/합성용 프롬프트 생성
- negative prompt 생성
- 개선 결과 이미지 슬롯
- mock 개선 결과 또는 placeholder 지원

주의:

- Pinterest API 실시간 연동은 포함하지 않습니다.
- 레퍼런스는 사용자가 업로드하거나 메모로 입력하는 방식부터 시작합니다.
- 고도화된 image-to-image 합성 품질은 구현 여건에 따라 mock 또는 후순위로 둡니다.
- 상품의 실제 스펙과 다르게 보이게 만드는 이미지는 피합니다.

### 6. AI 상세페이지 생성

- Vercel AI SDK 사용
- 에이전트 단계별 structured output 사용
- 13개 섹션 JSON 생성
- zod schema 기반 출력 검증
- 낮은 temperature 설정
- 상품 정보에 없는 효능, 인증, 수치 생성 금지
- 누락 섹션 fallback 처리
- mock fallback 처리

13개 섹션:

1. Intro
2. One Line Selling Point
3. Problem
4. Solution
5. Key Benefit 1
6. Key Benefit 2
7. Key Benefit 3
8. Detail Point
9. Use Scene
10. Recommended For
11. Trust Point
12. FAQ
13. CTA

### 7. 모바일 상세페이지 캔버스

- 사용자는 PC/노트북에서 작업합니다.
- 결과물은 모바일 상세페이지 형태의 세로형 캔버스로 보여줍니다.
- 캔버스는 실제 export 결과와 최대한 유사하게 표시합니다.
- 화면 미리보기용 크기와 export용 실제 크기를 구분합니다.

### 8. 데스크톱 반응형 작업 레이아웃

- 가로 모니터에서는 입력/섹션 목록, 모바일 캔버스, 편집 패널을 함께 볼 수 있게 구성합니다.
- 세로 모니터에서는 긴 모바일 캔버스를 더 크게 볼 수 있게 구성합니다.
- 세로 모니터에서는 보조 패널이 상단/하단, 접이식 패널, 탭 패널 형태로 전환될 수 있어야 합니다.
- 캔버스와 패널은 화면 높이에 맞춰 독립 스크롤이 가능해야 합니다.
- 상단 저장/export 작업 바는 화면이 좁아져도 접근 가능해야 합니다.
- 텍스트, 버튼, 패널이 겹치지 않아야 합니다.

지원할 대표 작업 환경:

- 일반 노트북 화면
- 일반 데스크톱 가로 모니터
- 세로로 회전한 데스크톱 모니터

### 9. Light/Dark 모드

- 앱 전체 UI는 light/dark 모드를 지원합니다.
- 사용자의 시스템 테마를 기본값으로 반영합니다.
- 사용자가 직접 light/dark/system 중 하나를 선택할 수 있습니다.
- 테마 전환 버튼은 상단 네비게이션 또는 사용자 메뉴에서 접근할 수 있어야 합니다.
- 편집기, 대시보드, 관리자 화면 모두 두 테마에서 읽기 쉬워야 합니다.
- 상세페이지 캔버스의 최종 디자인은 앱 테마와 분리합니다.
- export 결과물은 사용자가 선택한 상세페이지 디자인 무드와 스타일 세트를 기준으로 생성합니다.

### 10. 핵심 인터랙션 모션

업무 도구의 사용성을 해치지 않는 범위에서 GSAP 기반 인터랙션을 사용합니다.

원칙:

- 모든 화면을 과하게 움직이지 않습니다.
- 기획자 에이전트 수정 요청, 새 시안 제출, export 완료처럼 기억에 남는 순간에만 사용합니다.
- 모션은 빠르고 부드러워야 하며 작업을 방해하지 않아야 합니다.
- 사용자의 `prefers-reduced-motion` 설정을 존중합니다.

적용 후보:

- floating 기획자 에이전트 아이콘 클릭 시 원형 버튼이 패널로 확장되는 모션
- 수정 요청 패널 열기/닫기
- 새 시안이 제출될 때 변경된 섹션 하이라이트
- 섹션 순서 변경 후 settle animation
- export 완료 success motion

### 11. 블록형 편집기

- 섹션 문구 수정
- 섹션 이미지 교체
- 섹션 숨김/복구
- 섹션 순서 변경
- 추천 카피 후보 선택
- 특정 섹션 다시 생성
- 실행취소/다시실행 (Ctrl+Z / Ctrl+Shift+Z 단축키 + 상단 작업바 버튼)

실행취소/다시실행 범위:

- 문구 수정, 이미지 교체, 섹션 숨김/복구, 섹션 순서 변경, 새 시안 적용까지 편집기 내 모든 변경 동작을 히스토리 스택으로 관리합니다.
- 히스토리는 프로젝트를 여는 동안 메모리 상태로 유지하며, 새로고침/재접속 시 초기화되는 것을 기본으로 합니다.
- 버튼은 상단 작업바에 되돌리기/다시하기 한 쌍으로 배치하고, 되돌릴 항목이 없을 때는 비활성 상태로 표시합니다.

제공하지 않는 기능:

- 피그마식 자유 좌표 배치
- 임의 텍스트 박스 생성
- 레이어 패널
- 이미지 세밀 리사이즈
- 자유 드로잉 도구

위 기능은 이번 MVP에서 제공하지 않습니다. 다만 캔버스, 섹션, 텍스트, 이미지 컴포넌트는 나중에 더 세밀한 편집 기능으로 확장할 수 있도록 너무 강하게 결합하지 않습니다.

### 12. 기획자 에이전트 수정 요청

상세페이지 편집기 안에서 사용자가 새 시안 수정을 요청할 수 있는 기획자 에이전트 패널을 제공합니다.

목표:

- 사용자가 모든 문구를 직접 고치지 않아도 되게 합니다.
- 사용자의 요청을 단순 섹션 수정이 아니라 상세페이지 기획 변경으로 해석합니다.
- 기획자 에이전트가 재기획한 뒤 제작/검수 에이전트를 거쳐 새 시안을 제출합니다.

MVP 범위:

- 전체 시안 수정 요청
- 특정 섹션 중심 수정 요청
- 톤앤매너 변경 요청
- 첫 화면/인트로 방향 변경 요청
- FAQ/CTA 축약 요청
- 검수 경고를 반영한 재기획 요청
- 새 시안 제출 전/후 비교
- 새 시안 적용하기

제공 방식:

- 자유 채팅보다 빠른 액션 버튼을 우선합니다.
- 채팅 입력은 보조 수단으로 제공합니다.
- 사용자의 수정 요청, 기존 기획안, 제작 결과, 검수 결과, 상품 입력값, 톤앤매너를 전달합니다.
- 단순 텍스트 치환이 아니라 기획 → 제작 → 검수 루프를 다시 실행합니다.
- 다만 비용 제어를 위해 섹션 범위가 명확한 요청은 영향을 받는 섹션 중심으로 제한할 수 있습니다.

API 비용 제어:

- 수정 범위가 좁으면 관련 섹션과 기획 요약만 전달합니다.
- 전체 재기획이 필요한 요청은 프로젝트당 호출 횟수를 제한할 수 있게 설계합니다.
- mock fallback을 제공합니다.
- 응답은 짧은 structured JSON으로 받습니다.

확장 방향:

- 현재는 기획자 에이전트가 사용자의 수정 요청을 받아 재기획하는 구조로 제한합니다.
- 별도의 편집 에이전트를 만들지 않습니다.
- 사용자가 직접 수동 수정한 내용은 다음 프로젝트에서 기획자 에이전트가 참고할 스타일 신호로 저장합니다.
